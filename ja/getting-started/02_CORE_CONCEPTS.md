# Core Concepts

AIBOSは、AIを単体で動かすためのフレームワークではありません。

組織をAIと共に進化できる形へ設計するためのフレームワークです。

その中心となるのが、4つのコアコンセプトです。

```
Knowledge
      │
      ▼
Workers
      │
      ▼
Playbooks
      │
      ▼
Runtime
```

それぞれは独立していますが、お互いに連携することでAI Business OSとして機能します。

---

# Knowledge

## 「組織の記憶」

Knowledgeは、組織が持つ知識を管理します。

例えば、

- ブランド
- 商品
- サービス
- デザインガイドライン
- 技術資料
- 社内ルール
- 顧客情報
- 過去の意思決定

などです。

Knowledgeは単なるドキュメントではありません。

AIが理解できる形で整理された、

**組織の知識ベース**

です。

---

# Workers

## 「AIの役割」

Workersは、

AIに役職を与える仕組みです。

例えば、

```
Designer

Sales

Engineer

Writer

Researcher

Reviewer
```

それぞれが、

- 得意分野
- 判断基準
- 専門知識
- 話し方
- ゴール

を持ちます。

つまり、

Workerとは、

**人格ではなく役割**です。

---

# Playbooks

## 「仕事の進め方」

Playbookは、

組織が持つ業務プロセスです。

例えば、

```
LP制作

↓

ヒアリング

↓

競合分析

↓

構成作成

↓

デザイン

↓

レビュー

↓

公開
```

という流れを定義できます。

AIはPlaybookを読むことで、

「どう仕事を進めるべきか」

を理解します。

---

# Runtime

## 「AIBOSの実行エンジン」

Runtimeは、

Knowledge

Workers

Playbooks

を読み込み、

最適なAIへ渡します。

```
Knowledge
      │
Workers
      │
Playbooks
      │
Runtime
      │
GPT / Claude / Gemini
```

Runtimeは、

AIそのものではありません。

AIBOS全体を動かす実行環境です。

---

# なぜ分離するのか？

例えば、

Designer Workerは

Etsyでも

Web制作でも

広告制作でも使えます。

Playbookだけ変更すれば、

同じWorkerを再利用できます。

逆に、

同じPlaybookを

別のWorkerへ適用することもできます。

つまり、

```
Knowledge

×

Workers

×

Playbooks
```

を自由に組み合わせられることが、

AIBOS最大の特徴です。

---

# Everything is Modular

AIBOSは、

すべてをモジュールとして設計します。

```
Knowledge

+

Worker

+

Playbook

+

Runtime
```

必要なものだけ組み合わせる。

だから、

拡張しやすく、

共有しやすく、

再利用しやすい。

---

# Human-Led.

人は、

組織を設計します。

Knowledgeを書きます。

Workersを作ります。

Playbooksを改善します。

AIは、

それらを実行します。

だから、

AIBOSでは、

**人が主導し、

AIが増幅する。**

という思想を大切にしています。

---

# Summary

AIBOSは、

Knowledge

Workers

Playbooks

Runtime

という4つのコンポーネントによって構成されます。

これらを組み合わせることで、

AIは単なるチャットツールではなく、

組織の一員として継続的に価値を生み出します。
