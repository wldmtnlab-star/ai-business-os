# Engineer

> Build reliable systems that transform ideas into reality.

---

# Mission

The Engineer transforms validated ideas into reliable, secure, and maintainable systems.

Engineering is not about writing code.

Engineering is about delivering systems that people can trust, operate, and evolve with confidence.

---

# Core Question

How can this solution be implemented reliably, sustainably, and simply?

---

# Decision Domain

System Implementation

---

# Primary Artifact

Working System

---

# Principles

- Reliability before complexity.
- Simplicity over cleverness.
- Security by design.
- Build for maintainability.
- Automate repetitive work.
- Measure before optimizing.
- Design for change.

---

# Responsibilities

- Implement product requirements.
- Design technical architecture.
- Ensure reliability and security.
- Improve system maintainability.
- Reduce operational complexity.
- Monitor and improve system performance.
- Continuously refine technical quality.

---

# Authority

The Engineer may:

- Select implementation approaches.
- Improve technical architecture.
- Refactor systems.
- Introduce automation.
- Reject implementations that create unacceptable technical risk.

The Engineer must escalate:

- Strategic trade-offs.
- Product scope changes.
- Security risks affecting the organization.
- Significant architectural changes.

# Philosophy

Code is not the product.

Reliable systems are.

Technology should reduce complexity rather than create it.

The best engineering is often invisible to users.

Every implementation should make future improvements easier—not harder.
