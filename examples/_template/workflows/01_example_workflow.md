# Example Workflow

> Replace this document with a Workflow specific to your organization.

This template demonstrates how to document a repeatable Workflow using AI Business OS.

A Workflow describes how your organization consistently delivers a Service by combining people, knowledge, AI, and standardized processes.

---

# Objective

Describe the purpose of this Workflow.

Questions to consider:

- What problem does it solve?
- What outcome should it achieve?
- Which Service does it support?

---

# Scope

Define what is included—and excluded—from this Workflow.

Questions to consider:

- When should this Workflow be used?
- When should it not be used?
- What assumptions are made?

---

# Inputs

List everything required before the Workflow begins.

Examples:

- Customer request
- Requirements
- Existing documentation
- Design assets
- Technical specifications
- Project brief

---

# Roles and Responsibilities

Identify the people or teams involved.

For each role, describe:

- Responsibilities
- Decision-making authority
- Expected outputs

Example:

| Role | Responsibilities |
|------|------------------|
| Project Lead | Coordinate execution |
| Subject Matter Expert | Provide domain expertise |
| Designer | Produce visual assets |
| Developer | Build the solution |
| Reviewer | Verify quality |

---

# Workflow

Describe the sequence of activities.

Example:

```text
Discovery
      │
      ▼
Planning
      │
      ▼
Execution
      │
      ▼
Review
      │
      ▼
Delivery
      │
      ▼
Retrospective
```

Document each step.

---

## Step 1

Describe:

- Objective
- Activities
- Responsible roles
- Expected outputs

---

## Step 2

Repeat for each major step.

---

## Step 3

Continue until the Workflow is complete.

---

# Deliverables

Describe the outputs produced.

Examples:

- Documentation
- Software
- Reports
- Designs
- Presentations
- Training materials

Deliverables should create measurable value.

---

# Success Indicators

Describe how success is evaluated.

Examples:

- Customer satisfaction
- Delivery time
- Quality metrics
- Business impact
- Error reduction
- Team efficiency

Measure outcomes—not activity.

---

# Risks

Identify potential risks.

Examples:

- Missing requirements
- Resource constraints
- Technical uncertainty
- Communication gaps
- Scope changes

Describe how these risks are mitigated.

---

# AI Support

Describe how AI assists this Workflow.

Examples:

- Research
- Drafting documentation
- Summarization
- Brainstorming
- Code generation
- Quality checks

Human review remains essential for important decisions.

---

# Continuous Improvement

After each execution, ask:

- What worked well?
- What should improve?
- What knowledge should be documented?
- Should Playbooks be updated?
- Should Workers be improved?
- Should Organizational Memory be updated?
- Is a new ADR needed?

Every execution should strengthen the organization.
