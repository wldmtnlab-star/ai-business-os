# Contributing to AI Business OS

First of all, thank you for your interest in contributing to AI Business OS.

AI Business OS is an open framework for designing, operating, and continuously improving organizations.

Contributions of all sizes are welcome—from fixing typos to proposing new architectural ideas.

---

# Our Philosophy

AI Business OS is guided by a few core principles:

- Purpose before process
- Human-led, AI-amplified collaboration
- Continuous organizational learning
- Practical over theoretical
- Simplicity over complexity

Please keep these principles in mind when contributing.

---

# Ways to Contribute

You can contribute by:

- Improving documentation
- Fixing errors or inconsistencies
- Proposing new Workflows
- Creating Playbooks
- Building Workers
- Improving templates
- Sharing Reference Organizations
- Reporting issues
- Suggesting architectural improvements

Every contribution helps improve the framework.

---

# Before You Start

Before opening a Pull Request, please:

- Read the documentation.
- Search existing Issues and Pull Requests.
- Open a Discussion if you're unsure about a major change.

For architectural changes, we recommend discussing the proposal before implementation.

---

# Documentation Standards

When contributing documentation:

- Write clearly and concisely.
- Prefer practical guidance over theory.
- Use consistent terminology.
- Follow the existing document structure.
- Keep examples realistic.

Documentation should be easy to understand and easy to maintain.

---

# Architectural Changes

Changes that affect the architecture should be carefully considered.

Examples include:

- Repository structure
- Organizational architecture
- Knowledge model
- Workflow model
- Worker model
- Naming conventions

For significant changes, consider creating or updating an ADR (Architecture Decision Record).

---

# Pull Requests

When submitting a Pull Request:

- Keep changes focused.
- Explain why the change is needed.
- Reference related Issues or ADRs when applicable.
- Update documentation if necessary.

Small, focused Pull Requests are easier to review.

---

# Code Contributions

If contributing code:

- Keep implementations simple.
- Prefer readability over cleverness.
- Document important decisions.
- Follow the project's coding conventions.

Code should support the framework—not complicate it.

---

# Community

Please be respectful and constructive.

We value:

- Curiosity
- Collaboration
- Learning
- Thoughtful discussion

Healthy disagreement is welcome when it helps improve the project.
