# AI Business OS Standard

# 04_MARKDOWN

Version: 1.0

---

# Purpose

Markdown is the common language of AI Business OS.

It should remain simple, readable, and portable.

Documents should be understandable in any editor, repository, or AI system.

Formatting exists to improve understanding.

Never to decorate content.

---

# Philosophy

Structure before style.

Meaning before formatting.

Clarity before beauty.

Markdown is not documentation.

Markdown is the container of knowledge.

---

# Heading Structure

Use a logical heading hierarchy.

```text
# Title

## Section

### Subsection

#### Details
```

Never skip heading levels.

---

# Paragraphs

Keep paragraphs short.

Prefer:

One idea.

One paragraph.

Avoid walls of text.

---

# Lists

Use unordered lists for concepts.

- Item
- Item
- Item

Use numbered lists for sequences.

1. First
2. Second
3. Third

---

# Tables

Use tables when comparing structured information.

Example

| Item | Description |
|------|-------------|
| Purpose | Why the document exists |

Avoid tables for long explanations.

---

# Code Blocks

Use fenced code blocks.

Always specify the language.

Example

```yaml
version: 1.0
```

```text
Knowledge

↓

Execution
```

---

# Diagrams

Prefer simple text diagrams.

Example

```text
        ●
        │
        ▼
   Knowledge
        │
        ▼
   Execution
```

Documentation should remain readable without images.

---

# Emphasis

Use emphasis sparingly.

Use:

**Important**

Avoid excessive formatting.

Never rely on color.

---

# Links

Prefer relative links.

Example

```text
../knowledge/company.md
```

Avoid duplicated information.

Link instead.

---

# Images

Images support understanding.

They should never replace explanation.

Every diagram should also exist as text.

Accessibility comes first.

---

# File Length

Prefer smaller documents.

Recommended:

500–1500 words.

Split documents when responsibilities become unclear.

---

# Writing Rules

Every document should answer:

- Why?
- What?
- How?

When appropriate.

---

# AI Compatibility

Documents should be readable by:

- Humans
- Large Language Models
- Search systems
- Static site generators

Avoid formatting that depends on a specific platform.

---

# Review Checklist

Before publishing:

- [ ] Heading structure is correct
- [ ] One purpose only
- [ ] No duplicated information
- [ ] Links are valid
- [ ] Tables improve clarity
- [ ] Diagrams remain readable as plain text
- [ ] AI can understand the structure

---

# Closing

Simple documents create better understanding.

Better understanding creates better decisions.

Human-Led.

AI-Amplified.
